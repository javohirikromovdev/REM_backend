# REM frontend design previews

Created: 2026-11-08. Status: visual options awaiting user selection; no frontend implementation yet.

## Options

1. **Zamonaviy katalog** - white, royal blue, navy. Clear filter sidebar and information-rich cards. Recommended for the exam project because filtering and catalog browsing are immediately visible.
2. **Premium** - charcoal, ivory, champagne gold. Large architectural photos, serif headings, dark property detail view on mobile.
3. **Sokin va qulay** - warm ivory, forest green, sage, terracotta. Editorial split hero and a calm responsive catalog.

## Scope from the assignment and actual backend

Required future screens: Home/Explore, property catalog, property detail and inquiry form, login/register, seller dashboard and listing form, favorites, sent inquiries, admin moderation and users.

Backend supports city, category (id or slug), SALE/RENT, exact room counts, min/max price, newest/price sorting, pagination, images, favorites, sent inquiries, profile and listing moderation. Only APPROVED listings appear publicly; seller status labels must cover PENDING, APPROVED, REJECTED.

Implementation details to preserve when a style is chosen:
- Room filtering uses exact counts. Mockup chips reading 4+ must become 4 xona (or another exact count), unless the backend is explicitly extended later.
- Newest listings in the premium image are not a manually curated featured-list API.
- Category chips must be populated from the real category API, not hardcoded assumptions.
- Use API data for listing cards; image content and prices here are illustrative mockup data.
- Inquiry is a form and sent-inquiry list; no live chat, reply thread, payment, map, ratings or booking API is assumed.
- Respect actual property currency; no currency conversion is implied by the mockup prices.
- Build responsive, protected routes and loading/empty/error/unauthorized states in the selected style.
